AgentX 数据集中的一条会话:29 轮的输入 token 是怎么攒出来的

取 AgentX 公开数据集里的一条真实会话(编号 00ca01c4aaec…,全程约 42 分钟)。数据里没有任何文字,只有每一轮的 token 数和"哪些内容块之前出现过"。把它画出来,就能看到输入是一层一层叠上去的。

合计输入 3,971,584 · 输出 35,287 · 比例约 113:1输入里 93% 是可复用的前缀这条会话是怎么被测的 →AgentX 的重放机制 →

图一:每一轮的完整输入

每一行是一次请求递给模型的全部输入,长度按 token 数画。颜色表示这段内容是哪一轮第一次出现的:越浅越早,越深越晚。最右边金色的一小截是这一轮新加的。

较早的轮次带进来的内容(可复用) 较晚的轮次带进来的内容(可复用) 本轮新增(必须计算) 本轮输出(同一比例尺)

把鼠标停在任一色块上可以看它的来源和 token 数。条形右侧三列数字依次是:输入总量、其中新增的部分、输出。

从图上能读出什么

  • 输入像年轮一样只增不减。第 3 轮的输入 = 第 2 轮的全部输入 + 一小截新内容;第 4 轮 = 第 3 轮的全部 + 又一小截。到第 29 轮,最左边那一大段仍然是第 2 轮带进来的那 64,128 个 token。
  • 第 2 轮的那一大块是"开场白"。它一次带进来 6.4 万 token,之后每一轮都原样重复。按 Claude Code 的工作方式,这应该是系统提示、工具定义和最初的任务说明(这一点是推断,数据里看不到内容)。
  • 输出几乎看不见。橙色的输出条和输入用的是同一把尺子。输入十几万,输出几百到三千,所以只是一条细线。
  • 子智能体是另起一摞。三个子智能体不继承主智能体的上下文,各自从约 3.5 万 token 起步。第一个要从头算;第二、第三个的开头有 536 块与第一个逐字相同,可以复用。
  • 子智能体回来后,主智能体那一轮新增特别多。第 6 轮新增 16,000 token,因为三个子智能体的结果要写回主对话。
  • 停顿之后缓存还在不在,决定这一轮贵不贵。第 7 轮之前停了 433 秒。如果服务器把这条会话的缓存挤掉了,这一轮就不是算 2,400 个新 token,而是把 10 万 token 全部重算。

图二:放大看每轮新增的那一小截

图一里金色的部分太窄,这里单独放大。每轮新增的输入可以拆成三种来源:

上一轮模型自己的输出,被写回对话历史 子智能体交回的结果 工具返回的结果,或用户的新消息

这张图的拆分是估算:数据里只有新增块的总数,没有标注每块是什么。"上一轮输出回填"按上一轮的输出 token 数计,"子智能体结果"按各子智能体最后一次请求的输出计,剩下的归为工具结果或用户消息。第 6 轮的三段加起来与实际新增量对得上,第 17 轮的新增量(1,920)与第 16 轮的输出(1,914)几乎相等,说明这个拆法大体成立。

这和评测有什么关系

  • 绿色的部分考的是记性。服务器能把它留在缓存里,这一轮就只需要处理金色那一小截。留不住,整条都要重算。AgentX 的成绩差距主要来自这里。
  • 金色的部分考的是读得快不快。也就是预填充速度。
  • 橙色的部分考的是写得快不快。也就是解码速度,对应"每个用户每秒收到多少 token"。
  • 默认的吞吐数字是把整条都算进去的。这条会话完整放一遍,计入吞吐的是 4,006,871 个 token,其中真正需要计算的新增输入加输出只占一成左右。
  • 重放时,橙色和金色之间的联系被切断了。真实对话里,这一轮的橙色输出会成为下一轮金色新增的一部分。AgentX 重放时,下一轮写回历史的是事先准备好的填充文字,不是被测模型刚写出来的内容,所以每个被测系统拿到的输入完全相同。
