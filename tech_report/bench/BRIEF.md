# 基准调研任务说明(四组共用)

背景:DeepSeek 在 2026 年 9 月发布的 DeepSeek-V4.1-Flash 技术报告(arXiv:2609.19969)里用了一批评测基准。我们要为每个基准写一条调研卡片,最终汇成一份中文报告,帮助读者理解"DeepSeek 为什么选这些基准"。今天是 2026-11-10。

## 对每个基准要查清的内容
用网络搜索核实,优先一手来源(论文 arXiv 页、官方网站、官方仓库、排行榜),其次才是二手报道。经典基准你若已熟知可少搜,但 2025–2026 年的新基准必须搜索确认,不要凭印象写。

## 输出
把结果写成一个 JSON 文件(路径见各自任务),内容是一个数组,每个基准一个对象,字段如下,文字一律用简体中文(专有名词保留英文):

- `name`:基准名(与任务清单里的写法一致)
- `full_name`:全称或展开(没有就同 name)
- `year`:首次发布年份(字符串,如 "2024";该版本另有年份可写 "2023;v2.1 为 2026")
- `org`:提出的机构或团队
- `measures`:一句话,它测什么能力
- `format`:题目形式与规模(题量、任务类型、是否多语言/多模态、是否在容器里执行等)
- `metric`:常用指标及含义(如 EM、F1、Pass@1、Resolved、Rating)
- `status`:它在 2026 年的处境——是否已接近饱和、是否有数据污染/泄题争议、是否仍有区分度、当前顶尖成绩大致在什么水平(有可靠数字才写)
- `why_used`:业界为什么用它、它在同类基准中的定位(2–3 句,写事实和公认看法,不要写空话)
- `notes`:值得一提的细节或与其他基准的关系(如是谁的升级版、与谁配套)
- `sources`:数组,每项 `{"title": "...", "url": "..."}`,至少 1 条,最好 2–3 条
- `confidence`:"high" / "medium" / "low",并在 `caveat` 字段里用一句话说明不确定之处(没有就写空字符串)

## 纪律
- 查不到或无法确认的,如实写进 `caveat`,`confidence` 标 low,不要编造题量、年份、作者或分数。
- 版本号要对准:任务清单里若写了具体版本(如 Terminal-Bench 2.1、DeepSWE v1.1、FrontierSWE v2),要查该版本与前后版本的区别。
- 搜索请求里不要带任何个人信息或本项目路径。
- 只写指定的那个 JSON 文件,不要改动其他文件。写完后用 `python3 -c "import json;print(len(json.load(open('<文件>'))))"` 确认 JSON 合法。
- 最后的回复只需简短说明:完成了几个、哪几个把握不足及原因。
