## 3 通用基础设施

### 3.1 训练基础设施

#### 3.1.1 多模态训练基础设施

##### 对比学习中的通信-计算重叠。

视觉编码器(vision encoder)先用对比目标进行优化,再用生成式的下一 token 预测损失进行微调。在对比阶段,损失是在整个 batch 的文本-视觉对上计算的,因此两种模态的特征都必须在数据并行的各个 rank 之间做 all-gather,带来大量通信开销。由于文本特征的梯度只依赖于收集到的视觉特征,对称地,视觉特征的梯度也只依赖于收集到的文本特征,所以每一次 all-gather 都可以与前向或反向传播重叠执行,而不必让流水线停下来等待:

  -- ------------------------------------------------------------------------------------------------------------------------------------------------- --
     $$\text{Forward}(V)\;\rightarrow\;\bigl(\text{Forward}(T)\;\|\;\text{AllGather}(V)\bigr)\;\rightarrow\;\nabla_{\text{Text}}\\                     
     \;\rightarrow\;\bigl(\text{Backward}(T)\;\|\;\text{AllGather}(T)\bigr)\;\rightarrow\;\nabla_{\text{Vision}}\;\rightarrow\;\text{Backward}(V),$$   
  -- ------------------------------------------------------------------------------------------------------------------------------------------------- --

其中 $V$ 和 $T$ 分别表示视觉特征和文本特征,$(A\,\|\,C)$ 表示计算 $A$ 与通信 $C$ 重叠执行,$\nabla$ 表示梯度计算。在这一调度下,视觉特征在文本前向传播期间被收集,文本特征在文本反向传播期间被收集,于是两次 all-gather 都完全隐藏在有效计算之后。

##### 端到端并行。

为了应对视觉编码器与 LLM 之间在模型和数据上的异构性([Zhang et al., 2025b](#bib.bib56)),我们采用了近期训练系统中使用的解耦编码器设计([Team et al., 2025](#bib.bib54); [Team et al., 2026b](#bib.bib55))。视觉编码器被复制到 LLM 参数树之外,每个训练步被划分为三个阶段:视觉编码器前向、LLM 前向/反向、视觉编码器反向。这种分离避免了视觉编码器计算与 LLM 计算之间的相互干扰。经过负载均衡的视觉处理被限制在第一和最后一个阶段,而 LLM 阶段不含任何视觉计算,保留了纯文本训练的并行策略。

##### 长序列多模态训练优化。

DeepSeek-V4.1-Flash 在最长一百万 token 的序列上训练,在预训练和后训练阶段都有相当大比例的训练发生在超长序列长度上。在这样的序列长度下,多模态样本会造成严重的 I/O、CPU 和内存瓶颈。

- •
  均衡的图像分片。在预训练期间,单条图像密集的超长序列在加载时就可能耗尽一台主机的 I/O、CPU 和内存,因此每条序列的图像会按负载均衡的方式分片到各个 CP rank 上,并且每张图像恰好只加载一次。在图像只读取一次的前提下,只要满足下式,加载就能一直隐藏在计算之后:

    -- ---------------------------------------------------------------------------------------------------------------------------------------------------------- --
       $$\frac{N\times\rho}{B_{\mathrm{IO}}}<\frac{N\times C}{B_{\mathrm{GPU}}}\quad\Longleftrightarrow\quad\rho<\frac{B_{\mathrm{IO}}}{B_{\mathrm{GPU}}}\,C,$$   
    -- ---------------------------------------------------------------------------------------------------------------------------------------------------------- --

  其中 $N$ 是 token 数,$\rho$ 是每个 token 的原始字节数,$C$ 是每个 token 的计算量,$B_{\mathrm{IO}}$、$B_{\mathrm{GPU}}$ 分别是文件系统带宽和 GPU 带宽。由于 $N$ 被约掉,该判据只涉及每 token 的量($\rho$ 和 $C$),与序列长度和集群规模无关;$\rho$ 由视觉模块的配置决定(例如分辨率上限或空间下采样倍率)。因此,存储吞吐只会在每 token 计算量很低的小模型上(例如消融实验中)成为瓶颈,而生产规模的模型仍然受限于计算。
- •
  增量图像传输。除了上述均衡分片之外,强化学习的 rollout 只以增量方式把图像传给推理引擎,并把引擎在 CPU 侧的解码和预处理输出缓存到分布式文件系统上,供后续 rollout 和后续训练复用。

#### 3.1.2 面向 CSA2 的注意力共享训练

在第 [2.3](#S2.SS3) 节中,我们介绍了 CSA2,这是一种具有三种模式的注意力共享方法,其中一些模式会在多个层之间共享主 KV、索引器 K 和 Top-K 索引中的一项或多项。要在大规模分布式训练中支持 CSA2,除了注意力计算本身之外还需要额外的协调。具体来说,共享注意力组件的各层可能被放置在不同的流水线阶段(pipeline stage)上,这使得直接复用模块与传统的阶段本地执行方式不兼容。因此,我们采用了若干设计来支持 CSA2 训练。

影子索引器(shadow indexer)用来解决这一问题:在每个参与的阶段上放置一个轻量的可执行副本,同时为共享参数保留唯一的逻辑属主。属主仍然负责优化和 checkpoint,而参数同步和梯度聚合则让各个影子副本在整个训练过程中保持一致。这一设计保留了原有的模型语义,又不需要流水线调度器把共享层当作特殊的执行单元来处理。

流水线载荷扩展(pipeline payload extension)在源层与消费层跨越流水线边界时,为下游消费者提供所需的中间表示和稀疏路由信息。这些状态被并入已有的点对点通信路径,并按照与上下文并行(context parallelism)一致的方式切分,既避免了不必要的复制,又保持了相应的梯度流。

micro-batch 级的共享状态管理负责跟踪同时处于活跃状态的各个流水线 micro-batch 所关联的状态,并在前向执行、激活重计算和反向传播之间协调它们的生命周期。共享状态会一直保留到最后一个消费者完成为止,随后立即释放,以限制额外的内存开销。同一套运行时抽象还负责处理阶段放置和源-消费者关系,使注意力实现在访问共享状态时无需依赖物理的流水线布局。

再加上对优化器、checkpoint、warm-up 和计算图追踪流程的轻量适配,这些机制使 CSA2 能够在现有的分布式训练接口和流水线调度下透明地运行。

#### 3.1.3 Engram

Engram 的 embedding 表按行切分,分布在大小为 engram parallel size 的专用进程组上。组的大小控制着单设备内存用量与 embedding 查找的通信范围之间的权衡。优化器状态则进一步在每个表分区的各副本之间分片。Engram 的查找索引只取决于输入 token 序列。因此,在当前训练步中各流水线阶段开始处理 microbatch 之前,就会为整个本地 batch 发起 embedding 预取,从而把对流水线执行的干扰降到最低。embedding 梯度在反向传播期间被缓冲,并在主干反向传播结束后返还给各自所属的 rank。为了与多模态训练高效结合,embedding 预取和梯度传输被安排为与视觉编码器的前向和反向计算重叠执行。embedding 以 FP8 存储和取回,取回的数值和缩放因子直接传给后面的 GEMM。在 Engram 表更新方面,Sinkhorn 归一化会跨迭代维护行缩放向量和列缩放向量,以避免反复写入完整的归一化矩阵。行归一化与部分列统计量的累加被融合进同一个内核,以进一步减少内存流量。在 RL rollout 期间,Engram 的 embedding 表常驻于 GPU 内存中。这种放置方式减轻了主机内存压力,也有助于避免主机内存碎片导致的内存不足(out-of-memory)故障。

### 3.2 推理系统

DeepSeek-V4.1-Flash 在设计上把推理效率作为头等大事。尽管它的架构在概念上比较复杂,最终得到的推理内核流程却十分简洁。通过合理的内核融合(kernel fusion),我们把繁杂的操作封装起来,让硬件资源在少数几个融合内核内部保持完全流水化——其中包括 FlashMLA([Li and Liu, 2025](#bib.bib38))中的 fused-RoPE-attention-RoPE-cast 内核,DeepGEMM([Zhao et al., 2025](#bib.bib37))中的 Mega-Gate、Mega-mHC 和 Mega-MoE 内核,TileKernels([Wang et al., 2026a](#bib.bib39))中的各内核,以及 DeepSelect([Qian et al., 2026](#bib.bib40))中的 TopK 内核。结果是,绝大多数 Transformer 层(即 CSA2 工作在 Reuse 模式的那些层)在预填充(prefill)时只需执行 15 个内核,在解码(decode)时只需执行 11 个内核,从而同时实现了高吞吐和低延迟的推理。

在部署层面,我们采用编码器-预填充-解码(Encoder--Prefill--Decode,EPD)解耦,使视觉编码、预填充和解码能够各自独立扩缩,并在执行上相互重叠。

#### 3.2.1 持久化 KV 缓存管理

在相同负载下,V4.1 把持久化 KV 缓存(persistent KV cache)的占用降到了 V4 的 1/8。这一下降来自两个相乘的因素:持久化 KV 缓存不再存储 SWA KV,这使其大小几乎减半;而仍保留在其中的全局 KV,又通过架构和精度上的优化被进一步压缩到 V4 占用的 1/4。

在 V4 的部署中,SWA KV 占了持久化 KV 缓存容量的将近一半。在该缓存内,全局 KV 和 SWA KV 各自独立管理,由 LRU 淘汰策略控制。全局 KV 被完整存储,命中时复用整个前缀。与之不同,SWA KV 只在两个特定位置缓存——提示词的末尾和输出的末尾——以便支持重新生成和多轮会话;命中后可以从该缓存位置继续计算。为了保持较高的命中率,我们在 SSD 上配置了足够大的持久化 KV 缓存,使得在典型负载下两类 KV 都能驻留 72 小时以上。尽管只在指定位置保留 $n_{\mathrm{win}}$ 个 KV 条目,未经压缩的 SWA KV 缓存仍然带来了可观的存储开销,在每轮都很短的多轮对话中尤其如此。

持久化存储 SWA KV 既昂贵又低效,因为它的访问模式与持久化 KV 缓存的长保留策略并不匹配。全局 KV 呈现长尾式的复用,而 SWA KV 只会在活跃会话内一个很窄的、分钟级的窗口中被复用,一旦会话结束或下一轮开始就成了死数据。V4 技术报告曾提出 Zero SWA Caching,通过重新计算缺失的 SWA KV 来避免存储开销。然而,精确恢复需要对 $L\times n_{\mathrm{win}}$ 个 token 做一次完整的前向传播,这一代价在生产部署中被证明是难以承受的。

因此,V4.1 对持久化 KV 缓存管理做了如下修改:

1.  1.
    SWA KV 不再缓存在持久化 KV 缓存中,而是存放在一个分布式内存池里,该内存池由每台机器 10% 的主机 DRAM 划拨而成。虽然这个池的总容量要小得多,但它的 TTL 很短(只有几分钟),过期条目可以立即被回收给新会话使用;在真实负载下,这样的高周转率足以服务绝大多数并发的活跃会话。全局 KV 仍然留在持久化 KV 缓存中,并保证至少 72 小时的生命周期。
2.  2.
    淘汰 SWA KV 不可避免地会造成未命中,而借助一种轻量的兜底机制——编码器 SWA 有界重放(Encoder SWA Bounded Replay,详见第 [3.2.2](#S3.SS2.SSS2) 节),这种未命中的代价仍然可以承受。对于那些不可避免但并不常见的、命中全局 KV 却未命中 SWA KV 的请求,它只需重新计算 $n_{\mathrm{win}}$ 个 token 就能恢复缺失的状态,而不必做一次完整的 $L\times n_{\mathrm{win}}$ 个 token 的前向传播。这种有界重放是整个设计的基石:它把一次灾难性的未命中变成了平缓而廉价的降级,从而使把 SWA KV 移出持久化 KV 缓存的做法站得住脚。

#### 3.2.2 SWA 有界重放

由于 SWA 的依赖关系会逐层累积,要精确重建 $L$ 层的 SWA KV 就需要重放 $L\times n_{\mathrm{win}}$ 个 token。SWA 有界重放(SWA Bounded Replay)则只重放最近的 $n_{\mathrm{win}}$ 个 token,并把 SWA 截断到重放片段之内,接受近似的状态:对于从位置 $s$ 开始的重放,位置 $i$ 处的 query 关注 $\bigl[\max(s,\,i-W+1),\,i\bigr]$ 范围内的 SWA key。

##### 编码器 SWA 有界重放。

编码器 SWA 有界重放使前缀缓存只依赖于全局 KV,从而可以把 SWA KV 从持久化 KV 缓存中移除。

当编码器的 SWA KV 缺失时,我们重放已缓存前缀的最后 $n_{\mathrm{win}}$ 个 token,并把它们与未缓存的后缀一起处理。被重放的 token 只重新生成 SWA KV,直接复用已缓存的全局 KV,既不重算也不覆盖;而未缓存的后缀则同时生成全局 KV 和 SWA KV。

按照这一设计,重放得到的前缀状态是近似的,因此为未缓存后缀计算出的全局 KV 和 SWA KV 取决于缓存命中的位置,在不同位置之间并不在数学上完全一致。令人鼓舞的是,我们的实验证据表明,这种有界重放策略几乎不会损害回答质量。

##### 解码器 SWA 有界重放。

解码器 SWA 有界重放把解码器的前向传播限制在 $n_{\mathrm{win}}$ 个 token 之内,使预填充的总计算量几乎减半。

在 CED 下,解码器的全局 KV 是由编码器最终的隐藏状态投影得到的。让预填充在编码器处就结束的唯一障碍是解码器的 SWA KV:它由每个解码器层自身的隐藏状态生成,并且是最初几步解码所必需的。由于我们从不缓存解码器的 SWA KV,要精确重建它就需要让 $\frac{L}{2}$ 个解码器层在提示词最后 $\frac{L}{2}\times n_{\mathrm{win}}$ 个 token 上运行,当一个很长的已缓存前缀后面只跟着一小段未缓存后缀时,这样做代价很高。因此,我们在这一场景下同样采用有界重放策略:每次预填充时,我们都重放提示词的最后 $n_{\mathrm{win}}$ 个 token,把它们的编码器输出在同样的 SWA 截断下送过各解码器层,得到的解码器 SWA KV 只用于解码,不用于前缀缓存。

按照这一设计,重建出的解码器 SWA KV 与完整解码器前向传播得到的结果并不在数学上等价。同样,我们发现这一策略对回答质量的影响微乎其微。为了更加稳妥,我们还在后训练期间模拟了同样的重放,让模型在训练中就适应这一机制。

## 4 预训练

### 4.1 数据构建

##### 文本数据整理

为了追求更高的智能水平,我们不再局限于小规模数据实验所反映的、通用的样本级质量,而是更加关注能够提供独特信息增益的多样语料之间的整体相互作用。我们采用了更加系统化、标准化的数据构建流水线,以提升数据质量并优化数据配比。具体来说,基于更全面的评测,我们精心设计了一套覆盖模型参数量和训练数据量的规模阶梯(scaling ladder),用来指导大规模训练。我们过滤掉了信息增益有限的模型生成内容,包括能力较弱的模型的输出和低质量的机器翻译文本。我们把这类内容视为隐式重复,因为它们在很大程度上只是对已有信息的改写,在长时间的训练中可能变得有害。我们还探索了模型在环(model-in-the-loop)的数据迭代方法,为未来的大规模合成数据打基础。此外,我们引入了更多领域专家来构建细粒度的数据质量评估维度。与上一版本相比,新语料纳入了更多来自新发布的开源仓库、提交、库和新兴框架的较新代码,以覆盖更广泛的编程语言,并更好地反映当下真实的软件工程场景。

##### 多模态数据整理

我们的多模态预训练数据集主要由三类数据构成:图文对、图文交错数据和领域专用数据。我们的出发点是,原始网页数据天然地提供了丰富的多模态知识,因此我们没有做大规模的数据合成,而是优先清洗并以原生形态使用这些数据,从而在预训练期间实现最直接、最可扩展的视觉知识压缩。在最初的数据收集中,我们发现自己的爬虫系统过度偏向以文本为主的网页内容,于是我们从 Common Crawl 出发重新引导(re-bootstrap)了它,以提高对多模态来源的覆盖。对于图文数据,我们从网页中提取图像及其关联的 alt 文本,用图文相关性阈值进行过滤,并基于图像语义去重。对于交错数据,这一子集主要由网页和 PDF 构建而成。处理大规模多模态语料通常比处理纯文本语料需要更高的 CPU 和磁盘存储成本,这促使我们把交错数据的构建组织成成本逐级递增的若干阶段。在图像抓取之前,我们先用启发式和统计式过滤、去重以及质量模型挑选出高价值文档。留存下来的文档随后被组装成图文交错序列,并以感知图像的方式再次进行过滤和去重。最后,我们使用 SmolVLM([Marafioti et al., 2025](#bib.bib52))对图文内容进行严格的质量打分,从而提取出高质量的交错数据。在这一过程中被过滤掉的文档,有一部分会经过筛选和重组被回收为额外的图文对。为了弥补网络采集数据的固有局限,我们还纳入了领域专用数据集,以增强模型在细粒度视觉感知(例如视觉定位和指点)、光学字符识别(OCR)以及长尾知识获取方面的能力。我们还收集了大量图像-代码对和 computer-use 轨迹,以提升多模态的智能体式理解能力。

##### 数据整合与去重

由于纯文本数据和多模态数据是通过不同的流水线处理的,我们把最终的训练语料构建为这两个数据源的并集。对于重叠的样本,我们用其多模态版本替换纯文本版本,并采用两种配置中较大的 epoch 数。完成这一替换后,所得语料中纯文本数据与多模态数据的 token 比例为 $7{:}1$。我们通过联合预取和分配训练样本,尽量减少预训练与上下文扩展两个阶段之间的样本重叠。超长文档在混合之前会被确定性地预先切分,以保证训练 token 在各数据分片和各训练步之间均匀分布。我们还进一步改进了 best-fit 打包算法,使填充率不超过 $10^{-4}$。

### 4.2 预训练设置

#### 4.2.1 模型设置

我们把 Transformer 层数设为 40,隐藏维度 $d$ 设为 5120。我们采用因果编码器-解码器(Causal Encoder-Decoder)架构,编码器 20 层,解码器 20 层。前两层使用纯滑动窗口注意力。编码器其余 18 层使用压缩率 $m=2$ 的 CSA2。这些层被划分为配置完全相同的三组,每组六层。在每一组中,第一层工作在 Full 模式,其余五层工作在 Reuse 模式。解码器的 20 层使用压缩率 $m=1$ 的 CSA2。这些层被划分为五组,每组四层。在第一组中,第一层工作在 Full 模式,其余三层工作在 Reuse 模式。其余四组采用相同的配置:第一层工作在 Reindex 模式,其余三层工作在 Reuse 模式。对于所有 CSA2 层,我们把索引器 query 头数设为 32,索引器头维度设为 128,稀疏注意力选取的 KV 条目数(即注意力 top-k)设为 512。我们把 query 头数设为 64,头维度设为 512,query 压缩维度设为 1280。对于分层稀疏索引器(Hierarchical Sparse Indexer),我们最多选取 2,048 个块,每块 8 个位置,总计最多得到 16,384 个候选位置。输出投影的分组数设为 8,每个中间注意力输出的维度设为 1024。对于额外的滑动窗口注意力分支,窗口大小 $n_{\mathrm{win}}$ 设为 128。我们在所有 Transformer 块中都使用 MoE 层,采用带截断(clamping)的 SwiGLU 激活函数([OpenAI, 2025](#bib.bib41)),截断阈值为 10。每个 MoE 层由 1 个共享专家和 384 个路由专家组成,每个专家的中间隐藏维度为 2304。在路由专家中,每个 token 会激活 6 个专家。至于 mHC,扩展因子设为 4,Sinkhorn-Knopp 迭代次数设为 20。对于视觉编码器,我们把层数设为 32,隐藏维度设为 1024,注意力头数设为 16,图像 patch 大小设为 14。视觉 MLP 投影器有 2 层,隐藏维度为 5120。在这一配置下,DeepSeek-V4.1-Flash 的主干参数量为 552B,每个 token 在预填充时激活 8B,在解码时激活 16B。

#### 4.2.2 训练设置

我们对线性变换的参数使用 Muon 优化器([Jordan et al., 2024](#bib.bib31); [Liu et al., 2025](#bib.bib32)),对所有 RMSNorm 模块的权重和其他非矩阵参数使用 AdamW 优化器([Loshchilov and Hutter, 2019](#bib.bib60)),对所有 embedding 和预测头使用 Sinkhorn 均衡更新(Sinkhorn-balanced update)。对于 AdamW,我们把超参数设为 $\beta_{1}=0.9$、$\beta_{2}=0.95$、$\varepsilon=10^{-20}$ 以及 $\mathrm{weight\_decay}=0.1$。对于 Muon,我们把动量设为 $0.95$,权重衰减设为 $0.1$,并把每个更新矩阵的 RMS 重新缩放到 $0.18$,以便复用 AdamW 的学习率。对于 Sinkhorn 均衡更新,我们使用与 Muon 相同的动量系数和学习率修正因子,并设 $K=11$、$\tau=10^{-3}$、$\varepsilon=10^{-20}$。参照([Cheng et al., 2026b](#bib.bib50)),Engram 的学习率被放大 $5\times$。我们在 45T token 的多模态数据上训练 DeepSeek-V4.1-Flash,训练过程中没有出现不稳定。整个训练期间 batch 大小固定为 1.006 亿 token。学习率在前 2000 步线性 warm-up,随后保持在 $2.6\times 10^{-4}$ 直到 28T token。在 28T 到 40T token 之间,我们按余弦调度把学习率衰减到 $2.6\times 10^{-5}$。从 40T 到 45T token,学习率保持在这一数值。我们以 64K 的序列长度、带稀疏注意力从头训练模型,并在 34T token 处把序列长度扩展到 1M。对于无辅助损失的负载均衡,我们把图像 token 和文本 token 的偏置更新速度都设为 0.001,同时保留一个较小的序列级均衡损失,损失权重为 0.0001,以避免单条序列内部出现极端的不均衡。与 DeepSeek-V4 类似,我们在预训练期间采用样本级注意力掩码。

##### 视觉编码器训练。

我们的 DeepSeek-ViT 在与语言主干集成之前,先经过一个单独的训练阶段。训练流程由两个阶段组成:对比预训练和自回归微调。在对比预训练期间,我们使用 SigLIP([Zhai et al., 2023](#bib.bib59))提出的 sigmoid 对比损失,在约 47B 个来自 alt 文本数据的图文对上优化模型。为了从如此海量的数据集中高效地学习视觉表示,我们把最大输入分辨率限制为 $224\times 224$ 像素,对更大的图像在保持宽高比的前提下进行缩小。尽管在这一阶段使用更高的分辨率能带来明显的提升,但实验结果表明,这些收益对最终模型的贡献很小。因为后续的自回归阶段专门负责向高分辨率外推,在对比预训练期间提高分辨率会显著增加计算开销,却带不来多少整体改进。在自回归微调阶段,我们把视觉编码器接到一个 4B 的 MoE LLM 上,使用下一 token 预测目标,在包括图像描述、alt 文本、图表和 OCR 在内的数据集上训练 236B token。这一阶段旨在增强编码器对细粒度视觉特征的建模能力。因此,我们把输入分辨率约束在 $544\times 544$ 到 $1344\times 1344$ 像素之间,对超出范围的图像按比例缩放。这一阶段结束后,我们丢弃该 LLM,只保留优化后的视觉编码器用于后续的预训练流程,并在其中沿用相同的输入分辨率策略。

#### 4.3.2 评测结果

在表 [1](#S4.T1) 中,我们给出了 DeepSeek-V4-Flash、DeepSeek-V4-Pro 和 DeepSeek-V4.1-Flash 三者基座模型的详细对比,所有模型都在我们的内部评测框架下、采用严格受控且可复现的设置进行评测。与 DeepSeek-V4-Flash-Base 和 DeepSeek-V4-Pro-Base 相比,我们最新的基座模型展现出令人信服的效率提升。DeepSeek-V4.1-Flash 激活的参数量远少于 DeepSeek-V4-Pro-Base,KV 缓存占用也大幅降低,而性能却与前代模型完全持平。这些结果也反映出我们对预训练数据整理流水线所做的大幅改进。在这一版本中,我们引入了原生多模态训练,并通过相应的多模态评测验证了它的有效性。得益于在更多样的多模态语料上训练,DeepSeek-V4.1-Flash 的世界知识和理解能力达到了与 DeepSeek-V4-Pro 相当的水平。在推理和代码基准上,DeepSeek-V4.1-Flash 表现出一致的进步,在多个基准上达到了接近或优于 DeepSeek-V4-Pro 的性能。

为了进一步评估模型在真实研发场景中的能力,我们还在专门的内部语料上进行了困惑度(perplexity)测试。由于困惑度测试无法通过模型 API 完成,我们主要关注自己预训练的基座模型。在语料选择上,我们基于日常研发工作另行收集了一个评测集,包括内部文档、私有代码仓库和学术材料,它针对的是复杂科学问题和前沿研究上的推理、归因和问题求解。结果如图 [6](#S4.F6) 所示,其中我们报告了不同模型的 bits-per-byte(BPB),数值越低表示性能越好。
