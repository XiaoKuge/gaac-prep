# DeepSeek-V4.1-Flash:把 KV 缓存压缩推向极限

DeepSeek-AI\
research@deepseek.com

###### 摘要

长程智能体的广泛应用,使模型的工作负载越来越偏重输入。尽管已有工作大幅降低了长上下文计算的成本,预填充(prefill)的计算开销依然很高,庞大的 KV 缓存也持续挤占 HBM 与 SSD 的容量以及数据传输带宽。这些计算、存储和带宽需求叠加在一起,构成了进一步降低部署成本的主要瓶颈。为应对这一挑战,我们提出 DeepSeek-V4.1-Flash:一个多模态混合专家(Mixture-of-Experts,MoE)模型,主干参数量为 552B,支持最长一百万 token 的上下文。借助因果编码器-解码器(Causal Encoder-Decoder,CED)架构,模型在解码(decode)时每个 token 激活 16B 参数,而在预填充时只激活 8B 参数,显著提升了智能体式工作负载的成本效率。为了把 KV 缓存压缩推向极限,DeepSeek-V4.1-Flash 将压缩稀疏注意力 2(Compressed Sparse Attention 2,CSA2)中的跨层 KV 缓存复用与 FP4 KV 缓存结合起来。这些设计把全局 KV 缓存占用(始终位于 HBM 中)降到每 token 890 字节,约为 DeepSeek-V4-Flash 对应占用的 1/4。此外,通过一项名为 SWA 有界重放(SWA Bounded Replay)的专门部署优化,DeepSeek-V4.1-Flash 把持久化 KV 缓存占用(始终位于 SSD 或主机内存中)降到 DeepSeek-V4-Flash 的约 1/8。尽管 KV 缓存占用小得多,模型的性能仍大幅优于基线。除此之外,我们精简了 DeepSeek-V4 的架构,并引入了若干高效的架构扩展。我们在包含 45T token 的多模态语料上预训练 DeepSeek-V4.1-Flash,并进行了全面的后训练,使其在多种基于文本和多模态的智能体式场景中都有出色表现。模型 checkpoint 可在 [https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash) 获取。

## 1 引言

近年来,长程智能体的应用迅速扩展,超长上下文处理成为越来越重要的模型工作负载。支撑这类负载,不仅需要高效的长序列处理,还需要对庞大的 KV 缓存进行持久化存储、复用和传输。KV 缓存管理因此成为模型部署的一项基础能力,同时也在计算、存储和通信各方面带来了巨大挑战。此前在稀疏注意力上的进展([DeepSeek-AI, 2025](#bib.bib36); [DeepSeek-AI, 2026b](#bib.bib34))已显著降低了长序列处理的计算成本,这使得持久化存储和数据搬运成为日益突出的瓶颈。

具体而言,DeepSeek-V4([DeepSeek-AI, 2026b](#bib.bib34))把覆盖完整上下文的全局注意力分支与局部的滑动窗口注意力(Sliding-Window Attention,SWA)结合在一起。全局分支维护全局 KV,由主 KV 和索引器 K 组成;SWA 则维护局部 KV 状态。在窗口大小固定时,SWA 的 KV 存储有上界,与序列长度无关。因此,对足够长的序列来说,全局 KV 在运行时 KV 占用中占主导,而这部分占用受 HBM 容量限制。此外,部分 KV 会被持久化以供前缀复用,称为持久化 KV 缓存,它们受 SSD 和主机内存容量限制。I/O 与互连带宽也限制了缓存的迁移和加载。这些约束共同限制了服务吞吐,抬高了部署成本,并最终阻碍智能体在更长的任务跨度和更广的应用场景中的部署与普及。

因此,进一步降低 KV 缓存占用,对于缓解存储与通信瓶颈、降低长上下文服务成本至关重要。为此,我们开发了 DeepSeek-V4.1-Flash,一个为更激进的 KV 缓存压缩而设计的多模态混合专家(MoE)模型。DeepSeek-V4.1-Flash 拥有 552B 主干参数,原生支持多模态输入,可容纳最长一百万 token 的上下文。我们采用因果编码器-解码器(CED)架构,其中解码器的全局 KV 由编码器最后一层的隐状态投影得到。这一设计使模型在预填充时每 token 激活 8B 参数、在解码时激活 16B 参数,对输入密集的智能体式场景尤其划算。尽管规模远大于 DeepSeek-V4-Flash,在相同序列长度下,DeepSeek-V4.1-Flash 所需的运行时 KV 缓存存储只有其约 1/4,持久化 KV 缓存存储只有其约 1/8。不仅如此,DeepSeek-V4.1-Flash 的整体性能也优于 DeepSeek-V4-Flash。

这样的 KV 缓存压缩水平,来自模型架构、缓存精度和部署策略三方面的联合优化。从概念上看,DeepSeek-V4 可以视为一个基于 SWA 的局部处理主干,再辅以压缩后的全局上下文。这一视角促使我们把重点放在简化全局分支上,同时基本保留局部注意力的设计。在架构层面,我们设计了压缩稀疏注意力 2(CSA2),对全局 KV(包括主 KV 和索引器 K)以及 Top-K 索引做跨层复用,从而大幅减少 KV 缓存存储。CSA2 有三种静态指定的模式:Full、Reindex 和 Reuse。Full 模式生成全局 KV 并执行索引。Reindex 模式复用前面某一层的全局 KV,并用自己的索引器 Q 对共享的索引器 K 重新打分,选出新的 Top-K 索引。Reuse 模式同时复用前面某一层的全局 KV 和 Top-K 索引,直接执行稀疏注意力。在这三种模式下,每一层都保留自己的全局 Q 和 SWA KV。共享全局 KV 和索引器 K 减少了重复的缓存存储。此外,与采用压缩稀疏注意力(CSA)--重度压缩注意力(HCA)混合架构的 DeepSeek-V4 不同,DeepSeek-V4.1-Flash 使用纯 CSA2。在缓存精度层面,我们在训练中使用 FP4 全局 KV 缓存,性能只有轻微下降。CSA2 与 FP4 KV 缓存合在一起,把全局 KV 缓存存储降到 DeepSeek-V4-Flash 的约 1/4,如图 [1](#S0.F1)(b) 所示。在部署层面,DeepSeek-V4.1-Flash 与 DeepSeek-V4 一样,在每一层都使用滑动窗口注意力(SWA)。在 DeepSeek-V4 中,我们采用一种混合策略,在持久化 SWA KV 缓存的存储成本与精确重建所需的计算量之间取得平衡。精确重建需要重放最近的 $L\times n_{\mathrm{win}}$ 个 token,其中 $L$ 是层数,$n_{\mathrm{win}}$ 是 SWA 窗口大小。在 DeepSeek-V4.1-Flash 中,我们引入 SWA 有界重放,只重放最近的 $n_{\mathrm{win}}$ 个 token,近似重建所需的 SWA KV 状态。我们的实验表明,这样做带来的性能下降可以忽略不计。这一发现确立了一种新的存储--计算权衡:我们不必再把 SWA KV 缓存持久化到 SSD,代价只是少量的预填充重算。借助 SWA 有界重放,持久化 KV 缓存占用进一步降到 DeepSeek-V4-Flash 的约 1/8。这些优化合在一起,大大缓解了 HBM 和 SSD 的容量压力,降低了部署成本,并为更大规模的部署铺平了道路。

作为对 CED 和 CSA2 的补充,我们进一步精简了原有的 DeepSeek-V4 架构。此外,我们把原先的 mHC([Xie et al., 2026](#bib.bib42))设计升级为 Single-Pass mHC,并配套提供 Mega-mHC 部署内核,相比原来的四内核实现,激活值的内存访问量减半。我们还集成了 Engram([Cheng et al., 2026b](#bib.bib50))条件记忆模块来增强模型能力。同时,我们引入 DSpark([Cheng et al., 2026a](#bib.bib1))推测解码架构,通过半自回归的草稿生成和按置信度调度的验证来提升解码效率。综合所有这些架构改进后,DeepSeek-V4.1-Flash 的单 token 解码 FLOPs 在不同上下文长度下几乎保持恒定。图 [2](#S1.F2) 显示,上下文长度从 4K 扩展到 1M、增长 256 倍,其解码 FLOPs 只增加 1/4,增幅远小于 DeepSeek-V4-Flash。

为了充分兑现这些架构设计带来的 KV 缓存压缩收益,并进一步提升训练和推理效率,我们为 DeepSeek-V4.1-Flash 系统性地协同优化了训练基础设施和推理系统,确保大规模多模态训练和长上下文部署高效且可扩展。训练基础设施支持视觉编码器的分离式执行、面向长序列的均衡图像分片,以及用于注意力复用的跨阶段共享状态管理。推理系统实现了编码器和解码器两条 SWA 有界重放路径。进一步的优化包括通信--计算重叠、分片的 Engram 嵌入表,以及推理内核融合。特别地,每个 CSA2 Reuse 模式层在预填充时只需执行 15 个内核,在解码时只需 11 个。我们还在主机内存中把长生命周期的全局 KV 存储与短生命周期的编码器 SWA KV 分开,并用有界重放近似重建缺失的编码器 SWA 状态。

在预训练阶段,我们在包含 45T token 的大规模多模态语料上训练 DeepSeek-V4.1-Flash。稀疏注意力在 64K 的序列长度下从头训练,没有任何稠密注意力预热阶段。预训练之后,模型具备原生的多模态能力,并支持最长一百万 token 的上下文。在我们的评测中,DeepSeek-V4.1-Flash-Base 的世界知识、推理和编码能力与 DeepSeek-V4-Pro-Base 相当,并在留出(held-out)评测上取得 5%--10% 的提升,而总参数量只有后者的 1/3,激活参数量只有 1/4。这些结果共同凸显了它出色的参数效率,也反映出面向真实部署的训练数据质量有所提升。

在这个基座模型之上,我们进行后训练,以激发其推理和智能体式能力。与上文所述的架构创新不同,我们的后训练没有引入任何算法创新:训练配方遵循标准范式,即先做监督微调(SFT),再做强化学习(RL)和同策略蒸馏(OPD),除了 DeepSeek-V4 开发中已经成熟的做法([DeepSeek-AI, 2026b](#bib.bib34))之外没有任何改动。所有实质性的变化都在数据管线上。我们开发了大规模的自动化管线用于数据合成和环境构建,并逐步扩大 RL 中使用的数据、任务和 rollout 的规模,从而把模型的能力拓展到文本、多模态和智能体式各个领域。图 [1](#S0.F1)(a) 汇总了 DeepSeek-V4.1-Flash 在核心智能体式基准上的表现。我们的评测表明,尽管体量紧凑,DeepSeek-V4.1-Flash 展现出鲜明的能力特征:

- •
  推理。模型具备强大的推理能力,在数学、竞赛编程等推理密集型基准上保持高准确率,表现与 Kimi-K3([Team et al., 2026a](#bib.bib67))和 DeepSeek-V4-Pro 等顶尖开源模型相当。
- •
  智能体。在 Terminal-Bench 2.1([Merrill et al., 2026](#bib.bib21))、DeepSWE v1.1([DataCurve, 2026](#bib.bib15))和 AutomationBench([Shepard and Salimans, 2026](#bib.bib19))等标准智能体式基准上,DeepSeek-V4.1-Flash 的表现与闭源前沿模型持平。事实证明,它完全能够胜任日常编码任务和白领工作流。不过,在 Terminal-Bench 4.0([Marten et al., 2026a](#bib.bib75))这类需要专家级领域知识的科学向智能体式任务上,它与巨型模型之间仍有差距。
- •
  多模态。在多模态领域,模型在评测视觉推理和专业图表解读的基准上,超过了 Kimi-K3 等顶级开源竞品。除正式指标之外,它在前端开发、办公自动化等真实的视觉智能体式工作流中也体现出实用价值,能够利用渲染出的屏幕截图进行视觉检查和自我修正。尽管如此,我们承认,与巨型闭源系统相比,整体性能上仍存在明显差距。

这些结果表明,DeepSeek-V4.1-Flash 已经能够在绝大多数基准上与闭源前沿模型匹敌,并有能力完成 95% 以上的真实世界任务。同时,它较小的激活占用带来了较低的推理延迟和服务成本。因此我们认为,DeepSeek-V4.1-Flash 在能力与效率之间取得了良好的平衡,可以作为一个快速、平价的助手,支持广大用户的日常工作。总之,DeepSeek-V4.1-Flash 在降低部署成本的同时,提升了模型智能和推理效率。它大幅降低了大规模部署长程智能体的成本门槛,并为长程智能体在更广泛场景中的应用创造了新的机会。DeepSeek-V4.1-Flash 也是我们持续扩大规模的新起点。在此基础上,我们将推进模型架构、预训练和后训练的联合扩展,进一步探索模型智能的前沿。

## 2 架构

### 2.1 概览

DeepSeek-V4.1-Flash 是一个多模态混合专家(MoE)Transformer,以图像和文本为输入,自回归地生成文本。其语言主干由 40 个因果 Transformer 层组成,组织为一个 20 层的因果编码器加一个 20 层的解码器。除前两层只使用 SWA 外,每一层都同时包含全局注意力和滑动窗口注意力(SWA)。视觉编码器和 MLP 投影器把图像转换为视觉嵌入,与文本嵌入一起处理;多模态数据从语言模型预训练一开始就已纳入。总体上,DeepSeek-V4.1-Flash 有 552B 主干参数和 196B Engram 参数,预填充时每 token 激活 8B 参数,解码时激活 16B。图 [3](#S1.F3) 展示了 DeepSeek-V4.1-Flash 的整体架构。

因果编码器--解码器(CED)架构和压缩稀疏注意力 2(CSA2)分别针对长上下文推理中两类互补的成本。CED 用编码器输出来构建解码器的全局键值(KV)缓存,使大部分提示词 token 可以绕过完整的解码器计算,同时保留逐层局部的滑动窗口注意力。这使预填充计算量接近减半,降低了上下文不断增长的智能体式工作负载中处理新输入或未命中缓存输入的成本。CSA2 跨层共享全局 KV 以减少缓存存储,并复用稀疏选择结果以减少索引工作量。在解码器中,分层稀疏索引器(Hierarchical Sparse Indexer)把后续索引器的搜索范围限制在由较早索引器选出的候选池内,进一步减少了每个查询需要打分的条目数。

我们保留了 DeepSeekMoE([Dai et al., 2024](#bib.bib24))的共享专家和细粒度路由专家,并为图像 token 和文本 token 引入了分模态的负载均衡([Wang et al., 2024a](#bib.bib28))。Single-Pass mHC([Xie et al., 2026](#bib.bib42))修改了残差流的混合方式,以便实现更高效的内核融合;Engram([Cheng et al., 2026b](#bib.bib50))则加入了稀疏访问的条件记忆。我们在主干预训练中去掉了 MTP 模块,改用 DSpark([Cheng et al., 2026a](#bib.bib1))做推测解码。DSpark 在主干预训练阶段之后单独训练。此外,我们把主 KV 缓存压缩到 FP4,以进一步降低存储开销。后续各节将介绍这些组件以及相应的优化方面的改动。

#### 2.1.1 多模态架构

多模态输入通路由一个视觉编码器和一个 MLP 投影器组成。对每张输入图像,视觉编码器生成一个空间网格形式的视觉特征。随后,一个 $3\times 3$ 的 pixel-unshuffle 操作把每个局部邻域沿通道维重排,降低空间分辨率,再由 MLP 投影器把特征映射到语言主干的隐藏维度。最后,得到的视觉嵌入被插入输入嵌入序列中对应的图像 token 位置,由语言主干与文本嵌入一起处理。

##### DeepSeek-ViT

我们从头训练了一个名为 DeepSeek-ViT 的视觉编码器,用于原生处理不同分辨率的图像。DeepSeek-ViT 建立在 Vision Transformer([Dosovitskiy et al., 2021](#bib.bib79))架构之上,并做了若干修改。为了适应任意分辨率的输入,我们用 2D-RoPE 取代了标准的绝对位置嵌入。为了让 ViT 更贴近 LLM 的设计原则,我们把 patch 嵌入层的卷积换成线性投影,以确保与 Muon 优化器兼容。我们还采用 RMSNorm([Zhang and Sennrich, 2019](#bib.bib80))做归一化,采用 SwiGLU([Shazeer, 2020](#bib.bib23))作为激活函数。在把视觉特征送入 LLM 之前,我们施加一次 $3\times 3$ 下采样的 pixel-unshuffle 操作,把视觉 token 数量减少为原来的九分之一,从而有效支持最高约 $1344\times 1344$ 像素的输入分辨率。

##### 面向 MoE 的多模态无辅助损失负载均衡

图像 token 和文本 token 的表示分布不同,在 MoE 中可能引出不同的专家路由偏好。因此,只对它们的总负载做均衡,可能会掩盖各模态内部的不均衡。为解决这一问题,我们扩展了无辅助损失的负载均衡([Wang et al., 2024a](#bib.bib28)),为文本 token 和图像 token 分别维护一组逐专家的修正偏置。路由时,每个 token 使用与其模态对应的修正偏置来选择专家,而对被选中专家的输出加权时仍使用原始的路由分数。每个训练步之后,两组偏置根据各自的专家负载独立更新。这一设计在每个模态内部均衡了专家的利用率,有助于多模态训练的稳定和高效。

### 2.2 因果编码器-解码器(CED)

在智能体式工作流中,频繁的工具调用会产生大量预填充请求,一旦 KV 缓存未命中,就会带来沉重的计算开销。为缓解这一预填充瓶颈,我们受 YOCO([Sun et al., 2024](#bib.bib53))启发,提出因果编码器-解码器(CED)架构。YOCO 让上半部分的层直接共享下半部分生成的 KV 缓存,以此减少预填充计算。在这一思路的基础上,CED 引入了一系列结构改进,既提升了 KV 缓存的整体容量,也加深了 KV 生成的计算深度。结果是,CED 成功削减了近一半的预填充计算,同时保持与基线相当的性能。

对于全局注意力,CED 把 Transformer 底部的 $L/2$ 层作为因果编码器。对于上半部分的层(即解码器,$l>L/2$),KV 条目并不由各自的隐状态 $H_{l}$ 导出,而是使用依层而定的投影权重($W_{l}^{KV}$ 和 $W_{l}^{Z}$),直接从第 $(L/2)$ 层的隐状态 $H_{L/2}$ 投影得到:

  -- ------------------------------------------------------------------------------- -- -----
     $$C_{l}=H_{L/2}W_{l}^{KV},\quad Z_{l}=H_{L/2}W_{l}^{Z},\quad l>\frac{L}{2},$$      (1)
  -- ------------------------------------------------------------------------------- -- -----

其中 $C$ 和 $Z$ 分别表示 KV 条目及其对应的压缩权重。这一设计使 CED 在预填充阶段只需计算前一半的层,以极小的计算代价获得上层的全局 KV 缓存。

对于滑动窗口注意力(SWA),CED 在所有层上都保持常规的逐层计算。具体来说,对任意层 $l$,局部的键和值都直接由当前层的隐状态 $H_{l}$ 导出。这一设计有效增加了局部 KV 生成的计算深度。然而,保持这种逐层计算就需要一个 SWA 重放过程。在预填充阶段,为解码器计算 SWA KV 缓存需要额外处理 $n_{\mathrm{win}}\times L/2$ 个 token(其中 $n_{\mathrm{win}}$ 表示窗口大小)。对于每轮提示词都很短的多轮交互,解码器中的这部分计算开销不可忽略。幸运的是,已有工作([Chen et al., 2025](#bib.bib58))表明,SWA 实际的有效感受野远小于理论上的 $n_{\mathrm{win}}\times L/2$。受这一观察启发,我们引入解码器 SWA 有界重放(Decoder SWA Bounded Replay),在 SWA 计算中只预填充提示词的最后 $n_{\mathrm{win}}$ 个 token,从而显著降低计算成本。更多细节见第 [3.2.2](#S3.SS2.SSS2) 节。

总体而言,对于序列长度 $N\gg n_{\mathrm{win}}$,CED 把预填充复杂度从 $\mathcal{O}(NL)$ 降到 $\mathcal{O}(NL/2+n_{\mathrm{win}}\times L/2)\approx\mathcal{O}(NL/2)$,相当于把整体计算量减半。

### 2.3 压缩稀疏注意力 2(CSA2)

服务长上下文,需要同时控制 KV 缓存存储和注意力计算。这些成本可以沿三个相乘的维度来削减:条目大小,其中 GQA([Ainslie et al., 2023](#bib.bib3))减少 KV 头的数量,MLA([DeepSeek-AI, 2024a](#bib.bib27))让各个头共享一个小的隐变量;序列维度,即把每 $m$ 个 token 压缩成一个条目,如 DeepSeek-V4([DeepSeek-AI, 2026b](#bib.bib34))中的 CSA 和 HCA;以及层维度,即某些层复用其他层的缓存([Brandon et al., 2024](#bib.bib73))和选择结果而不保留自己的,或者干脆被更高效的层替换。已有工作表明,沿层维度做压缩是有效的:IndexCache([Bai et al., 2026](#bib.bib69))跨层复用 Top-K 索引以削减索引器计算;YOIO([Sun et al., 2026b](#bib.bib70))只计算一次稀疏路由并在所有层间共享;HySparse([Gao et al., 2026](#bib.bib71))让稀疏层复用稠密层的 KV 缓存。然而,只做索引复用并不能节省主 KV 存储,全网络范围共享路由会限制性能,混合式设计则仍然保留了完整注意力层;更重要的是,这些方法没有一个能覆盖全部三个相乘的维度。

CSA2 联合利用这三个维度:它跨层共享主 KV 和索引器 K,并允许各层复用 Top-K 索引,其中缓存共享与索引复用是解耦的。它把这些复用策略与一个简化的压缩器以及一个分层稀疏索引器结合起来,后者缩小了解码器中后续索引层的搜索域。

与 CSA 类似,CSA2 包含一个轻量的索引器,它用索引器 Q 和索引器 K 给主 KV 条目打分,并为每个查询选出 Top-K 个条目。每个 Q 同时关注被选中的条目和逐层局部的滑动窗口 KV(SWA KV)。CSA2 也把未压缩的主 KV 设置作为压缩比为 1 的特例包含在内。同时,CSA2 简化了压缩器和索引器。在 CSA 中,压缩比为 $m$ 时,每个主 KV 条目由 $2m$ 个原始 KV 缓存条目生成,相邻压缩条目的源条目相互重叠。它还在压缩时加入绝对位置嵌入,用来编码这 $2m$ 个条目的位置。CSA2 去掉了这种重叠和绝对位置嵌入。此外,CSA2 通过投影主 KV 条目来得到索引器 K,取代了 CSA 中从隐状态出发的独立压缩通路。这两项设计都简化了实现,并提高了训练效率。

第 [2.3.1](#S2.SS3.SSS1) 节和第 [2.3.2](#S2.SS3.SSS2) 节分别介绍跨层复用策略和分层稀疏索引器。

#### 2.3.1 跨层 KV 与索引复用

每个 CSA2 层被静态指定为三种模式之一:Full、Reindex 或 Reuse。在这三种模式下,该层都会计算自己的查询和 SWA KV,并把它们与选中的主 KV 条目一起使用,产生新的注意力输出。各模式的区别在于如何获得主 KV、索引器 K 和 Top-K 索引。图 [4](#S2.F4) 展示了这三种模式。

Full 模式。该层计算自己的主 KV 和索引器 Q,由这份主 KV 投影出索引器 K,并运行索引器产生新的 Top-K 索引。因此它执行完整的 CSA2 计算路径,各组件的职责与 DeepSeek-V4 中一个完整的 CSA 层相同。

Reindex 模式。该层复用前面某一层最近可用的*主 KV*及其对应的*索引器 K*。索引器计算自己的查询,对复用的键重新打分,并产生新的 Top-K 索引。这样,稀疏选择可以随层变化,而主 KV 和索引器 K 保持共享。

Reuse 模式。该层复用最近可用的*主 KV*,以及前面某个 Full 或 Reindex 模式层针对这份主 KV 计算出的最新*Top-K 索引*。它直接用这一选择结果执行注意力,既不计算索引器 Q,也不计算索引分数。

共享主 KV 和索引器 K 减少了缓存存储,而复用 Top-K 索引则避免了额外的索引器计算。Reindex 模式在保留缓存共享的同时,允许被选中的条目随层变化。当 CSA2 与 CED 结合时,被指定为 Full 模式的解码器层由第 $(L/2)$ 层(即因果编码器的最后一层)的隐状态计算自己的全局 KV。Reindex 和 Reuse 模式保持不变。

#### 2.3.2 分层稀疏索引器

跨层索引复用减少了索引器的求值次数,但剩下的索引器仍要对因果可见的全部上下文打分。对于极长的上下文,这一成本仍是主要的计算瓶颈。已有工作通过在 token 级索引之前先对池化的块表示进行打分和剪枝,引入了索引器稀疏性([Xu et al., 2026b](#bib.bib72))。我们发现,在解码器中,较浅层索引器的信息可以很自然地用来限制较深层索引器考虑的候选,而无需增加任何额外状态。因此我们引入分层稀疏索引器,它只用于 CED 的解码器,以减少解码过程中这种重复打分。对每个查询,第一个被指定为 Full 模式的层构建一个候选池,后面做重新索引的层以它作为搜索域。在候选池大小固定时,这把较深层索引器每个查询的成本从随上下文长度线性增长变为常数。该机制是训练感知的,并在后训练阶段引入:候选限制在训练和推理中以完全相同的方式施加,因此较深层的索引器是在与推理时相同的搜索域下优化的。图 [5](#S2.F5) 展示了这一过程。

这第一个 Full 模式层对所有因果可见的主 KV 位置打分,并为自己的注意力产生 Top-K 索引。它还执行按块的候选选择:每个块被赋予其内部各位置索引分数的最大值,分数最高的若干块被选中。随后,它把选中块所覆盖的位置收集成一个候选池,这个池比最终的 Top-K 集合更大。例如,选出 2,048 个块、每块 8 个位置,就得到 16,384 个候选位置。这个池决定了后续索引器在哪里搜索;最终的 Top-K 选择则决定每一层读取哪些主 KV 条目。

后续处于 Reindex 模式的层只对相应查询的候选位置打分,并在这个池内选出自己的 Top-K 条目。处于 Reuse 模式的层不做新的索引,而是使用针对其所复用的主 KV 计算出的最新 Top-K 索引。因此,候选池在各索引层之间共享,而它们的最终选择可以不同。

在候选池大小固定时,每个后续索引器为每个查询打分的位置数有上界,与上下文长度无关。第一个 Full 模式层仍然要扫描整个因果可见范围。因此,分层索引降低了后续索引器求值的成本,同时保留了最初那一遍全范围扫描。

### 2.4 高效的架构扩展

#### 2.4.1 Single-Pass mHC

在 DeepSeek-V4 中,我们引入了 mHC([Xie et al., 2026](#bib.bib42)),它在相邻的 Transformer 块之间维护 $n$ 条残差流。对每个 token,我们把这些流记为 $X_{l}\in\mathbb{R}^{n\times d}$,其中 $l$ 是块的编号,$d$ 是隐藏维度。这些流按如下方式更新:

  -- --------------------------------------------------------------------------------------------------------- -- -----
     $$X_{l+1}=B_{l}X_{l}+C_{l}\,\mathcal{F}_{l}(A_{l}X_{l}),\qquad(A_{l},B_{l},C_{l})=\mathcal{H}(X_{l}),$$      (2)
  -- --------------------------------------------------------------------------------------------------------- -- -----

其中 $A_{l}\in\mathbb{R}^{1\times n}$、$C_{l}\in\mathbb{R}^{n\times 1}$ 和 $B_{l}\in\mathbb{R}^{n\times n}$ 是由 $X_{l}$ 预测出的逐 token 系数。系数预测器 $\mathcal{H}$ 包含归一化和投影。

理想情况下,两个块之间的残差变换是一个从 $(X_{l-1},Y_{l-1})$ 到 $(X_{l},\hat{X}_{l})$ 的单一映射,其中 $\hat{X}_{l}=A_{l}X_{l}$ 是当前块的输入,$Y_{l-1}=\mathcal{F}_{l-1}(\hat{X}_{l-1})$ 是前一个块的输出。这样的映射需要 $(n+1)d$ 次读和 $(n+1)d$ 次写,因此激活值内存访问量的下界是 $(2n+2)d$。在实践中,DeepSeek-V4 对 ([2](#S2.E2)) 采用多遍实现,由于数据依赖,三个内核依次执行:

  -- ------------------------------------ ----------------------------------------------- -- --------------------------------------- -- -----
     $\displaystyle X_{l}$                $\displaystyle=B_{l-1}X_{l-1}+C_{l-1}Y_{l-1}$      残差更新,对 $n$ 收缩      (3)
     $\displaystyle(A_{l},B_{l},C_{l})$   $\displaystyle=\mathcal{H}(X_{l})$                 系数计算,对 $nd$ 收缩        (4)
     $\displaystyle\hat{X}_{l}$           $\displaystyle=A_{l}X_{l}$                         输入混合,对 $n$ 收缩         (5)
  -- ------------------------------------ ----------------------------------------------- -- --------------------------------------- -- -----

这三个内核分别读取 $(n+1)d$、$nd$ 和 $nd$ 个值,总共写入 $(n+1)d$ 个值。算上 $\mathcal{F}_{l}$ 中的 pre-norm,激活值内存访问总量为 $(4n+4)d$,是下界的两倍。

在 $\mathcal{H}$ 中,归一化权重被离线折叠进投影权重,RMS 除法则在投影之后施加。因此,三个阶段中的两个可以共用对残差的一次遍历:残差更新不需要沿隐藏维度做归约,所以 $X_{l}$ 的每个 tile 一经算出,就可以立即用来累加投影输出以及计算 RMS 所需的平方和。输入混合无法融合进这一遍,因为 $A_{l}$ 要等到对所有隐藏 tile 的归约完成后才可用。因此它需要第二次读取 $X_{l}$。这第二遍也可以把输入 pre-norm 一并纳入。这种两遍实现总共需要 $(3n+2)d$ 次激活值读写,比下界多读一次 $X_{l}$。

因此我们引入 Single-Pass mHC,把输入混合系数平移一个块,即每个块使用前一个块产生的混合系数,于是上述依赖消失:

  -- ----------------------------------------------------------------------------------------------------------- -- -----
     $$X_{l+1}=B_{l}X_{l}+C_{l}\,\mathcal{F}_{l}(A_{l-1}X_{l}),\qquad(A_{l},B_{l},C_{l})=\mathcal{H}(X_{l}).$$      (6)
  -- ----------------------------------------------------------------------------------------------------------- -- -----

现在输入混合使用 $A_{l-1}$ 而不是 $A_{l}$,因此不再依赖由 $X_{l}$ 计算出的系数。$X_{l}$ 的每个 tile 可以立即同时用于输入混合和系数预测,无需等待完整的归约。从实验上看,这一平移带来的性能下降可以忽略。

在预训练中,我们保留现有的多内核实现,因为这一平移只改变了每个块应用哪一组混合系数。在部署中,我们把残差更新、输入混合和系数预测融合成一个内核,即 Mega-mHC。该内核实现 mHC 时需要 $(3n+2)d$ 次激活值读写,实现 Single-Pass mHC 时需要 $(2n+2)d$ 次激活值读写。Mega-mHC 沿隐藏维度按 tile 处理 $X_{l}$。每个 tile 既用来计算混合后的输入,也用来累加为下一个块预测 $(A_{l},B_{l},C_{l})$ 所需的量。该内核还纳入了输入 pre-norm 和 FP8 转换。这样,残差只读一次、写一次,达到了理想映射的 $(n+1)d$ 次读和 $(n+1)d$ 次写,并把我们原始实现的激活值内存访问量减半。

#### 2.4.2 Engram

我们为 DeepSeek-V4.1-Flash 加入了 Engram([Cheng et al., 2026c](#bib.bib2)),这是我们在此前工作中提出的条件记忆模块,用于把记忆与计算解耦。我们沿用 Engram 的原始设计---分词器压缩、多头哈希、上下文感知门控和多分支集成---并做了两处修改。第一,我们去掉了短因果卷积,因为在我们的推理栈中,它带来的性能增益不足以抵偿所增加的复杂度。第二,我们用基于动量的更新加 Sinkhorn 平衡来优化 Engram 嵌入,详见第 [2.5](#S2.SS5) 节。

我们把 196B Engram 参数平均分配给两个模块。每个模块使用的 $N$-gram 阶数为 $\{2,3,4\}$,每个阶数有 8 个哈希头,总嵌入维度为 2048。每个头索引一张约 16M 条目的表,各表的大小取互不相同的素数。嵌入表和键/值投影都使用 FP8 精度。这两个模块放在第 1 层和第 14 层(从零开始编号),以均衡训练流水线各阶段的内存使用。推理时,确定性寻址使嵌入可以通过后台 RDMA 传输从主机内存预取,其中第一个模块的预取与第一个 Transformer 块的计算重叠进行。Engram 训练和推理的更多实现细节在第 [3.1.3](#S3.SS1.SSS3) 节讨论。

#### 2.4.3 DSpark

我们为 DeepSeek-V4.1-Flash 配备了 DSpark([Cheng et al., 2026a](#bib.bib1)),这是一个推测解码模块,把半自回归的草稿生成与按置信度调度的验证结合起来。草稿模型由三个 Transformer 块组成,滑动注意力窗口为 128 个 token。在这些块上做一次前向传播,即可并行算出五个草稿位置的基础 logits,同时由一个轻量的马尔可夫头建模草稿 token 之间的依赖关系。一个置信度头预测每个位置的条件接受概率,用来估计前缀存活概率。调度器把这些估计与实测得到的引擎吞吐曲线结合起来,为每个请求动态选择验证长度,目标是在当前系统负载下最大化全系统的期望 token 吞吐。

DeepSeek-V3([DeepSeek-AI, 2024b](#bib.bib33))中的 MTP 模块在整个预训练过程中与主干联合训练;与之不同,DSpark 是在预训练之后的一个专门阶段引入的。在这一阶段,我们只训练 DSpark,并保持主干冻结。在后训练期间,我们继续让 DSpark 与主干一同训练,但不把 DSpark 目标的梯度传回主干。这使 DSpark 始终与不断演化的策略保持对齐,从而既能加速在线服务,也能加速 RL 和 OPD 的 rollout 生成。

#### 2.4.4 FP4 主 KV 缓存

长上下文的智能体工作负载需要为每个请求维护很大的 KV 缓存,这抬高了服务成本。DeepSeek-V4 已经对 FP4 的索引器查询和键使用了量化感知训练(QAT)([Jacob et al., 2018](#bib.bib5)),既加速索引计算,也减小索引器缓存的大小。我们采用 OCP 标准的 MXFP4 格式([Rouhani et al., 2023](#bib.bib4)),以支持尽可能多的硬件平台,尽管在我们的实验中其他格式的精度更高。现在我们把 QAT 扩展到主 KV 缓存,在这里 FP4 的作用是减少存储,而不是加速矩阵乘法。在注意力之前先把缓存值反量化,让我们可以使用一种精度更高的格式,而不要求硬件对该格式提供原生的矩阵乘法支持,从而保持跨硬件平台的兼容性。

在评估过的几种约四比特格式中,我们选择 E2M1,并为每 16 个通道配一个 E4M3 缩放因子;这一做法沿用 NVFP4([Alvarez et al., 2025](#bib.bib6)),但省去了它的第二级全局缩放因子,以兼顾精度和简洁。省去这一缩放因子后,主 KV 缓存仍有充足的动态范围:该格式支持的幅值最高可达 $448\times 6=2688$,远高于缓存的幅值上界。在 DeepSeek-V4.1-Flash 中,训练得到的 RMSNorm 权重的最大幅值约为 $1$。经过 RMS 归一化后,$512$ 通道的 KV 隐变量的 L2 范数最多约为 $\sqrt{512}$。RoPE 保持这一范数不变,所以旋转之后各通道绝对值的最大值也以约 $\sqrt{512}\approx 22.6$ 为界。此外,训练中观察到的最大幅值在 $10$ 左右。因此,省去全局缩放因子不会造成可测量的精度下降,并且简化了缓存布局。

为了在 DeepSeek-V4.1-Flash 中启用 FP4 主 KV 缓存存储,我们在后训练阶段引入 QAT。非 RoPE 部分和 RoPE 部分使用相同的量化格式。我们在 RoPE 之后对缓存做量化:在我们的实验中,在 RoPE 之前量化只带来极小的精度提升,却会在解码时引入额外开销。由于 SWA KV 缓存对量化敏感,我们对它保留 FP8。与 DeepSeek-V4 中的 FP8 主 KV 缓存相比,这种格式使存储占用接近减半,无论是在 HBM 中还是卸载到 SSD 时都是如此。

### 2.5 优化

在 DeepSeek-V4 所用优化配置的基础上,我们做了一些新的修改,使其与架构设计更加契合。

第一,我们使用逐头的 Muon(head-wise Muon),即先把 Query 权重按头拆开,再施加 Muon 更新。这里简要讨论这一设计的动机。如果把 Muon 看作一种预条件梯度下降,原始 Muon 对所有头使用同一个预条件子,而逐头 Muon 为不同的头提供不同的预条件子。这一设计能更好地应对注意力头之间的异质性 [Zhang et al., 2024](#bib.bib64); [Zhang, 2026](#bib.bib66), Section 3。结果上,我们观察到逐头 Muon 优于原始 Muon。逐头 Muon 在实验上的优势也在 GLM 5([Zeng et al., 2026](#bib.bib68))和 Kimi-K3([Team et al., 2026a](#bib.bib67))中得到了验证。

第二,对新引入的 Engram 参数使用 Adam,会大幅增加优化器状态的内存占用。为了减少训练时的内存使用,我们改用基于动量的更新加 Sinkhorn 平衡,来优化 Engram 嵌入表、token 嵌入和预测头。Sinkhorn 平衡此前已在 SinkGD([Scetbon et al., 2025](#bib.bib61))中用于线性层的权重矩阵;这里我们把它扩展到这些大型参数矩阵上。与 Muon 一样,这种方法只需要一个动量缓冲区,同时在实验上优于 Adam。

##### 基本配置。

对于归一化层权重以及其他非矩阵参数(包括偏置和缩放因子),我们保留 AdamW([Loshchilov and Hutter, 2019](#bib.bib60))。对于语言模型主干中线性变换的权重矩阵、Engram 投影层以及视觉-语言投影器,我们使用 Muon([Jordan et al., 2024](#bib.bib31))。对于 Query 和 Key 权重,我们使用逐头 Muon。我们对 Muon 施加解耦权重衰减和 Nesterov 动量([Nesterov, 1983](#bib.bib35); [Liu et al., 2025](#bib.bib32));归一化层权重同样施加权重衰减,而偏置和缩放因子不施加。Sinkhorn 平衡的更新同样使用 Nesterov 动量,但不施加权重衰减。在预训练期间,我们在学习率衰减阶段之前保持视觉编码器冻结,而它的最后一个归一化层和视觉--语言投影器保持可训练。学习率开始衰减时,我们解冻视觉编码器,并以较小的学习率让它与 LLM 联合优化。

##### 用于 Engram / 嵌入 / 预测头的 Sinkhorn 平衡更新。

完整流程汇总在算法 [1](#alg1) 中。从总体上看,它遵循与 Muon 相同的工作流程,只是用 Sinkhorn 平衡取代了 Newton--Schulz 正交化。我们把矩阵中较大的那个维度记为 $m$,对嵌入表和预测头而言它对应词表大小;把隐藏维度记为 $n$。

CAPTION:: 算法 1 带 Sinkhorn 平衡的动量更新

1: 权重 $W_{t}\in\mathbb{R}^{m\times n}$、梯度 $G_{t}$、动量 $M_{t-1}$、动量系数 $\beta$、基础学习率 $\eta_{t}$、学习率修正 $\gamma$、数值常数 $\varepsilon$ 和 $\tau$,以及奇数个归一化步数 $K$

2: $M_{t}\leftarrow\beta M_{t-1}+(1-\beta)G_{t}$

3: $\widehat{G}_{t}\leftarrow\beta M_{t}+(1-\beta)G_{t}$ $\triangleright$ Nesterov 动量

4: $\rho_{i}\leftarrow\lVert\widehat{G}_{t,i,:}\rVert_{2}$ 且 $\bar{\rho}\leftarrow\frac{1}{m}\sum_{i=1}^{m}\rho_{i}$

5: $U^{(0)}\leftarrow\widehat{G}_{t}$

6: 若 $\rho_{i}\leqslant\tau\bar{\rho}$,则置 $U^{(0)}_{i,:}\leftarrow 0$ $\triangleright$ 屏蔽接近零的行

7: for $k=1,\ldots,K$ do

8:   if $k$ 为奇数 then

9:    for all $i=1,\ldots,m$ do

10:      $U^{(k)}_{i,:}\leftarrow U^{(k-1)}_{i,:}/(\lVert U^{(k-1)}_{i,:}\rVert_{2}+\varepsilon)$

11:    end for

12:   else

13:    for all $j=1,\ldots,n$ do

14:      $U^{(k)}_{:,j}\leftarrow U^{(k-1)}_{:,j}/(\lVert U^{(k-1)}_{:,j}\rVert_{2}+\varepsilon)$

15:    end for

16:   end if

17: end for

18: $\Delta_{t}\leftarrow\sqrt{n}\,U^{(K)}$ $\triangleright$ 把单位行 $\ell_{2}$ 范数转换为单位行 RMS

19: $\widetilde{\eta}_{t}\leftarrow\gamma\eta_{t}$ $\triangleright$ 匹配 Adam 的更新幅度

20: $W_{t+1}\leftarrow W_{t}-\widetilde{\eta}_{t}\Delta_{t}$

给定 Nesterov 动量更新 $\widehat{G}_{t}$,Sinkhorn 平衡寻找对角缩放矩阵 $D_{r}$ 和 $D_{c}$,使得

  -- --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- -- -----
     $$\Delta_{t}=\sqrt{n}\,U^{(K)}=\sqrt{n}\,D_{r}\widehat{G}_{t}D_{c},\qquad\frac{1}{n}\sum_{j=1}^{n}(\Delta_{t})_{ij}^{2}\approx 1,\qquad\frac{1}{m}\sum_{i=1}^{m}(\Delta_{t})_{ij}^{2}\approx 1,$$      (7)
  -- --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- -- -----

因此,该流程使更新矩阵的逐行 RMS 和逐列 RMS 近似相等。这里,一行对应一个 token 索引或一个 n-gram 标识,一列编码一个隐藏特征。Sinkhorn 平衡通过同时沿行和列做归一化,来利用这种 token--特征结构。为了数值稳定,满足 $\rho_{i}\leqslant\tau\bar{\rho}$ 的行会被屏蔽。因子 $\sqrt{n}$ 把单位行 $\ell_{2}$ 范数转换为单位逐行 RMS。另外,我们把有效学习率调整为 $\widetilde{\eta}_{t}=\gamma\eta_{t}$,以匹配 Adam 的更新幅度。我们取 $\gamma=0.18$,这与 Moonlight([Liu et al., 2025](#bib.bib32))中使用的因子 $0.2$ 接近。

更广泛地说,Sinkhorn 平衡与那些利用矩阵或张量轴结构的优化器密切相关([Shazeer and Stern, 2018](#bib.bib62); [Zhang et al., 2025a](#bib.bib63); [Wen et al., 2025](#bib.bib83); [Glentis et al., 2025](#bib.bib93); [Deng et al., 2026](#bib.bib81); [Yuan et al., 2026](#bib.bib82); [Xu et al., 2026a](#bib.bib84))。例如,Adafactor([Shazeer and Stern, 2018](#bib.bib62))以另一种方式做逐行和逐列归一化,Adam-mini([Zhang et al., 2025a](#bib.bib63))则对嵌入表和预测头使用另一种逐行归一化。这些归一化策略在优化性能和通信开销上可能有所不同。更细致的研究留作未来方向。
